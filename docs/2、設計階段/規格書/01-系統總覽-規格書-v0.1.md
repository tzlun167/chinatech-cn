## 1. 系統目標

重建 www.chinatech-cn.com，取代已 EOL 的 WordPress/WooCommerce 舊站，並提供：

1. **公開官網** — 關於我們、品牌、產品型錄（39 項）、聯絡方式
2. **後台管理** — 非技術人員可自助維護商品與頁面
3. **商品上架** — 商品 CRUD、分類、圖片、規格、上下架
4. **到訪監控** — 流量統計與熱門內容分析

**非目標（除非委託人另行要求）：** 購物車、線上付款、會員系統、金流物流。

## 2. 技術棧建議

### 2.1 推薦方案（首選）

| 層 | 選型 | 理由 |
|---|---|---|
| 應用框架 | **Next.js 15**（App Router, TypeScript） | SSR/SSG → 修正舊站 SEO 缺陷；前後台同專案 |
| 後台 CMS | **Payload CMS 3**（Node/TS，內嵌 Next.js） | **開箱即有後台 UI、商品 collection、媒體庫、權限**；不需從零寫管理端 |
| 資料庫 | **PostgreSQL 16**（已在本機運行） | 沿用環境；Payload 官方支援 |
| 樣式 | Tailwind CSS + shadcn/ui | 快速建立一致 UI |
| 到訪監控 | **Umami**（自架，Docker） | 輕量、隱私友善、開源、自架無月費；後台看得到報表 |
| 部署 | PM2（Node）或 Docker Compose | 視最終主機而定 |

**為何選 Payload CMS 而非自寫後台：**
需求 R1（後台管理）＋ R2（商品上架）本質就是 CMS 的標準功能。自寫等於重造輪子，且要自行處理權限、富文本、圖片上傳、排程發佈。Payload 以 TypeScript 定義 collection 即可同時得到：

- 後台管理介面（`/admin`）
- REST / GraphQL API
- 商品 schema 與驗證
- 媒體上傳與尺寸衍生
- 角色權限（admin / editor）
- 版本歷史與草稿

且與 Next.js 同進程 → **單一部署單元**，維運單純。

### 2.2 替代方案（供比較）

| 方案 | 優點 | 缺點 | 適用 |
|---|---|---|---|
| **A. Payload CMS + Next.js**（推薦） | 一套程式、TS 型別安全、免月費 | 需自行維運 Node/DB | 本專案 |
| B. Strapi + 前端框架 | 社群大、外掛多 | 生態多為 JS、型別較弱；需分離部署 | 若團隊熟悉 Strapi |
| C. Directus + 任意前端 | 直接掛既有 DB、UI 強 | 需自建 DB schema，CMS 邏輯較薄 | DB-first 情境 |
| D. WordPress 重架（新版） | 內容遷移最快、外掛現成 | 仍是 PHP + 外掛維護 + 攻擊面 | 若要求「最快上線」 |
| E. 純自寫 NestJS + 前端 | 完全掌控 | 後台 UI 全部自造，工期最長 | 有特殊流程需求時 |

> ⚠️ **D 方案（WordPress）** 雖可最快用外掛達成三項需求，但與「重建以擺脫 EOL 技術債」的初衷衝突。除非委託人明確要求優先上線速度。

### 2.3 到訪監控選型

| 方案 | 類型 | 說明 |
|---|---|---|
| **Umami**（推薦） | 自架開源 | 單容器 + PG，UI 直覺，免 Cookie 橫幅 |
| Plausible | 自架開源（CE） | 相似，社群版功能較少 |
| Matomo | 自架開源 | 功能最全（可取代 GA），較重 |
| Google Analytics 4 | 雲端免費 | 零維運，但資料在 Google、需 Cookie 同意 |
| 自建事件表 | 自寫 | 最輕，但無現成報表 UI，等於重造 |

**建議：Umami 自架**（資料自主、無月費、與 Postgres 共用）。

## 3. 功能規格

### 3.1 公開站（前台）

| 編號 | 功能 | 說明 | 來源 |
|---|---|---|---|
| F-01 | 首頁 | 公司簡介摘要、主打商品、聯絡資訊 | 舊站 `/` |
| F-02 | 關於我們 | 公司沿革、代理品牌、服務項目 | 舊站 `/` |
| F-03 | 品牌頁 | 代理品牌列表（Aim TTi、Laplace、N4L、NTi、Voltech、ACCORDANCE…） | 舊站 `?page_id=6078` |
| F-04 | 商品型錄 | 39 商品，卡片式排版，支援分頁 | 舊站 `?page_id=5201` |
| F-05 | 商品分類篩選 | 依分類（14 類）篩選 | 舊站 `product_cat` |
| F-06 | 商品搜尋 | 關鍵字搜尋（名稱／型號／描述） | 舊站搜尋 |
| F-07 | 商品詳細頁 | 主圖 + 相簿、描述、規格、所屬分類、相關商品 | 舊站 `?product=` |
| F-08 | 聯絡我們 | 電話／Email／地址／地圖 | 舊站 `?rs_elements=` |
| F-09 | 詢價表單 | 商品頁「詢問此商品」→ 寄信 | **新增**（待確認） |
| F-10 | 語意化網址 | `/products/<slug>`、`/brands`、`/about`、`/contact` | **修正舊站缺陷** |
| F-11 | SEO | sitemap.xml（正確網域）、meta、OG、結構化資料 | **修正舊站缺陷** |

## 4. 非功能需求

| 類別 | 要求 |
|---|---|
| 效能 | 首頁 LCP < 2.5s（4G）；商品圖 lazy load + WebP |
| SEO | 語意化網址、正確 sitemap、meta／OG、結構化資料（Product） |
| 安全 | 密碼雜湊、CSRF 防護、上傳檔型別白名單、後台限 IP 或強密碼、HTTPS |
| 相容 | 現代瀏覽器（Chrome／Edge／Safari／Firefox 近兩版）+ iOS/Android |
| 語系 | 簡體中文為主（沿用）；**多語待確認** |
| 備份 | DB 每日備份 + 上傳目錄備份 |
| 維運 | 單一部署單元優先；日誌可追 |

## 5. 資料遷移（舊站 → 新站）

已有素材：

- `參考-舊站/商品資料/商品清單-含描述.json`：39 商品（標題、描述、分類、圖片 URL）
- 商品圖片可從 `www.chinatech-cn.com/wp-content/uploads/` 下載後重新入庫

| 步驟 | 工作 | 備註 |
|---|---|---|
| 1 | 解析商品 JSON → 結構化（name / model / categories） | 名稱需人工清理（行銷詞、錯字、重複） |
| 2 | 下載 39 組商品圖片 | 需確認授權與畫質 |
| 3 | 建立分類與品牌主檔 | 14 分類 + 品牌清單 |
| 4 | 匯入 Payload（seed script） | 一次性腳本，可重跑 |
| 5 | 補齊 14 筆缺漏描述 | ⚠️ 需向委託人／原廠索取 |
| 6 | 合併重複商品 | TG1006 ×2、WA301 ×2 需確認是否同一品 |
