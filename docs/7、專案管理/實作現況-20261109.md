## 2. 啟動方式

### 2.1 官網（Port 3000）— 已由 systemd 託管

```bash
# 狀態／啟停（日常用這個）
systemctl --user status cts-web.service
systemctl --user restart cts-web.service
systemctl --user stop cts-web.service

# 看日誌
journalctl --user -u cts-web.service -f
```

- Unit 檔：`~/.config/systemd/user/cts-web.service`
- 已 `enable`（`WantedBy=default.target`）＋ 使用者 `Linger=yes`
  → **開機自動啟動、登出不停、當掉自動重啟**
- 程序 CGroup 在 `cts-web.service` 底下，**與 OpenClaw session 完全脫鉤**

> ✅ **dev 模式是刻意的**：本機（`devtest`, `192.168.1.32`）是**開發機**，
> 跑 dev 模式方便改碼即時生效。**正式站台部署到他處**（參照 Apex-wealth 模式：
> 本機開發 → 部署到 `192.168.1.34`），production build 在部署階段才做。

> ⚠️ 教訓：曾用 `setsid nohup` 與 PM2 常駐，兩者都會隨 OpenClaw exec session
> 結束（或被清理）而死亡。**服務要跨 session 存活，必須交給 systemd。**（詳見 §5.2）

手動啟動（僅除錯用，不建議對外）：

```bash
cd /home/dev/project/chinatech-cn/app && npm run dev
```

### 2.2 到訪監控（Port 3100）

```bash
cd /home/dev/project/chinatech-cn/monitoring
docker compose up -d      # 啟動
 docker compose ps        # 狀態
docker compose down       # 停止
```

## 5. 技術決策與踩過的坑

### 5.1 為何選 Payload CMS 而非自寫後台

需求 R1（後台）＋ R2（商品上架）本質就是 CMS 標準功能。Payload 以 TypeScript 定義 collection 即可同時得到後台 UI、REST/GraphQL API、權限、版本歷史、媒體庫，且與 Next.js 同進程 → **單一部署單元**。

### 5.2 關鍵教訓

| 問題 | 根因 | 解法 |
|---|---|---|
| `create-payload-app` 無法非互動執行 | TTY 初始化失敗（`uv_tty_init EINVAL`） | 直接抓 GitHub `3.x` 分支的 `templates/blank` |
| 模板相依為 `workspace:*` | 抓到的是 monorepo 開發版 | 改寫為正式發行版本 `3.93.0` |
| seed 匯入 400「invalid relationships」 | 關聯 ID 傳入**字串** | 必須維持**數字**型別 |
| 含中文 slug 的商品詳情頁 404 | **Next.js 16 傳入的 `params.slug` 是百分比編碼未解碼** | 查詢前 `decodeURIComponent` |
| 圖片大量下載失敗（`fetch failed`） | 舊站 JSON 內圖片網域 `www.gd.chinatech.com.tw` 已 NXDOMAIN | 改寫為實際存活的 `www.chinatech-cn.com` |
| `pkill -f "next-server"` 自殺 | pattern 匹配到自己的命令列 | 用明確 PID，或 `[n]ext-server` 括號技巧 |
| exec session 結束會殺掉 dev server | 程序未脫離 session | 曾用 `setsid nohup`（**不可靠**，見下行） |
| 重跑 `seed:images` 後商品全變草稿 | 該腳本未帶 `--publish`，會覆寫狀態 | 重跑 `seed:publish` 恢復 |
| 服務隨 exec session 死亡（反覆踩到） | `setsid nohup` 與 **PM2 都仍屬該 session 的 child group**，session 一收就被連帶殺掉 | 改用 **systemd user service**（§2.1），已驗證可跨 session／登出存活 |

### 5.3 已修正的舊站缺陷

- **語意化網址**：舊站 `/?product=xxx` → 新站 `/products/<slug>`
- **sitemap 網域錯誤**：舊站 sitemap 指向 `gd.chinatech.com.tw` → 新站待產出正確 sitemap
- **SEO metadata**：新站有 title/description/OG + Product 結構化資料
- **圖片 alt**：全部媒體都有替代文字
